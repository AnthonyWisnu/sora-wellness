# Frontend wellness

React + TypeScript untuk studio contoh. Halaman utama sekarang menggunakan API backend melalui proxy Vite `/api/v1` ke `http://127.0.0.1:3000`. Jalankan PostgreSQL, migrasi, seed, dan backend sesuai [README backend](../backend/README.md), lalu dari folder `frontend` jalankan:

```powershell
npm install
npm run dev
```

Buka alamat lokal Vite. Backend harus berjalan agar jadwal dan akun dapat dimuat. `npm run build`, `npm run lint`, dan `npm run format:check` memeriksa kode; `npm run format` merapikannya. `npm run smoke:site` memeriksa empat halaman publik dan lebar ponsel tanpa mengubah data. `npm run smoke:dashboard` memeriksa sidebar tiga peran, navigasi, refresh, Back/Forward, dan drawer ponsel memakai akun di `backend/.qa/demo-accounts.json`. `npm run smoke:live` memeriksa alur browser publik, booking, paket, admin, serta memastikan `/?demo=1` tidak membuka aplikasi simulasi. `npm run smoke:health` memeriksa profil pelanggan, persetujuan dan penghapusan kesehatan, daftar peserta dan absensi pelatih, serta koreksi admin. `npm run smoke:admin` memeriksa panel pengelolaan staf, reset sandi, jenis kelas, paket, sesi, dan jadwal berulang. `npm run smoke:content-lockers` memeriksa editor konten dan loker. `npm run smoke:admin-finance` memeriksa transaksi admin. Skrip browser memakai Microsoft Edge pada port 5173. Screenshot disimpan di `.qa/`.

Menu **Konten publik** di dashboard admin sekarang menyimpan perubahan sebagai draf. Admin dapat mengubah profil, blok Beranda/Jadwal/Paket/Kontak, testimoni, FAQ, kontak, peta, serta footer; pilih **Pratinjau draf** untuk membuka `/?preview=1`, kemudian **Terbitkan situs**. Pratinjau hanya tersedia untuk akun admin. Halaman publik mengambil versi terbit dari `GET /api/v1/public/site`; harga, kapasitas, dan jadwal tetap diambil dari endpoint operasional.

Tampilan public memakai export Stitch di `../Referensi UI/stitch_zeira_sanctuary_desktop_landing_page` sebagai acuan untuk Beranda, Jadwal, dan Membership; Kontak memakai gaya yang sama. Dataset demo Sora mengisi CMS dengan foto studio hasil generasi di `public/images/sora-*.png`; gambar dari CMS dipakai untuk hero dan galeri. Foto `sora-studio-hero.png` juga menjadi fallback saat CMS belum memiliki gambar. Blok keunggulan dan testimoni kosong menampilkan konten berlabel **Konten demo**; dataset demo mengisinya dengan teks contoh fiktif. Urutan dan visibilitas blok situs terbit tetap diatur admin. Skrip `npm run smoke:site` menyimpan screenshot empat halaman dalam ukuran desktop dan ponsel di `.qa/`.

Halaman utama menggunakan API untuk profil studio, paket, dan jadwal. Pelanggan dapat daftar/login, membeli atau memperpanjang paket, melihat status member, booking gratis/jatah/satuan, membuka Snap Sandbox, memeriksa status pembayaran, melihat saldo dan transaksi, serta membatalkan booking. Pembelian paket yang belum dibayar kedaluwarsa setelah 15 menit; perpanjangan mengikuti batas 30 hari dan maksimal satu paket berikutnya. Admin dapat mencari akun, membuat staf dengan sandi sementara acak, mereset sandi setelah verifikasi offline, mengelola jenis kelas dan pilihan paket, membuat/mengubah/membatalkan sesi, membuat jadwal mingguan, mengubah kebijakan, serta mengelola pengaturan Midtrans Sandbox. Server Key tidak ditampilkan pada respons baca atau disimpan di `localStorage`.

Pelanggan dapat mengubah nama, menyimpan catatan kesehatan opsional dengan persetujuan, dan menghapus seluruh catatan/snapshot miliknya. Pelatih dapat membuka kelas yang dia ajar, melihat peserta terkonfirmasi dan catatan kesehatan yang diizinkan, lalu mencatat absensi sejak kelas dimulai sampai 24 jam setelah selesai. Admin dapat mengoreksi absensi dengan alasan dan melihat audit tanpa membaca kesehatan. Admin juga dapat mengunggah dan memilih logo/foto, mengubah teks beranda, membuat nomor loker, dan menetapkan nomor kepada member aktif. Member melihat nomor loker yang ditetapkan di dashboard. Menu Transaksi admin menampilkan booking, pembayaran kelas/paket, saldo pelanggan, dan buku transaksi yang dapat dicari serta dipaginasi melalui API. Status member pada halaman nyata dihitung dari paket di backend; tidak ada akun member terpisah. Pembayaran kartu uji Sandbox sampai status `capture` sudah diuji untuk kelas dan paket: webhook HTTPS mengonfirmasi kelas, sedangkan tombol **Periksa status** mengaktifkan paket tanpa webhook.

Skrip `node scripts/sandbox-checkout.mjs booking|package|pay-booking|pay-package|verify-booking|refresh-package|cleanup` dipakai untuk uji checkout Sandbox nyata. Skrip membuat akun uji dan menyimpan URL Snap sementara di `.qa/sandbox-checkout.json` yang diabaikan Git. Jalankan mode pembayaran hanya dengan kartu uji resmi Midtrans. Mode `cleanup` menghapus akun dan transaksi uji dari database lokal serta berkas state; riwayat transaksi di Midtrans Sandbox tetap ada.

Kode aplikasi dibagi menjadi `src/app` untuk susunan halaman dan navigasi, `src/features` untuk alur tiap fitur/peran, `src/shared` untuk klien API, tipe respons, dan format, serta `src/styles` untuk CSS yang diimpor berurutan. Aplikasi hanya memakai API backend; prototipe lama, data mock, serta perintah demo sudah dihapus.

Foto `sora-*.png` dibuat dengan imagegen untuk studio fiktif Sora. Logo `sora-mark.svg` dibuat dalam format vektor; `sora-mark.png` adalah salinannya untuk pustaka media CMS.
